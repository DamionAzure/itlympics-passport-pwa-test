Scan a booth (no camera needed)

Generates a real, currently-valid code for that booth — using the same rotation interval set on the QR Booth page — and runs it through the same validation the camera path uses.

Geofence (campus-only scanning)

Gates the real Passport page's booth-code scanning to within a radius of campus — checked on the attendee's phone (works offline too, GPS needs no connection) AND re-checked server-side in validate_booth_code, so it can't be bypassed by editing the page's JS. It does not stop someone from feeding the browser a fake GPS reading in the first place (devtools location override, a mock-location app) — nothing short of comparing against the venue's own network can do that. Off by default so the app stays testable from anywhere; flip it on once staff are actually on campus. Takes effect on every phone within seconds, no redeploy. Only admins can change these (enforced server-side); everyone can read them, since there's no secret in an on/off switch and a public coordinate.

Other tests

Per-table wipe

Deletes every row from one cloud table — for resetting between test runs without touching the others. This only hits Supabase; it doesn't touch this device's local passport (use Full reset above for that), and it needs a confirmed cloud connection. booth_secrets is deliberately left off this list — wiping it breaks code generation for every booth until re-seeded.

Mock data

Generates fake attendees with real writes — same tables and same code paths as an actual Registration or a real vote, just with made-up names and student IDs, so the Dashboard has something to look at. Not simulated locally like the booth scans above: these rows really land in Supabase.

Live skills registrations

Updates in real time via Supabase Realtime as people register on any device — no polling, no Pusher needed. Needs Replication enabled on skills_registrations in the Supabase dashboard.

Manage roles

Everyone starts as user. Promote a teammate to staff (booths, entrance, dashboard, sections) or admin (everything, including wiping data and changing geofence settings). They have to have logged in once first so their account exists. Only admins can do this — enforced by the database, not just this button.

Manage sections

The Skills Registration page's course/section list — currently seeded from the SQL above. Add or remove one here instead of hand-editing the table; every device picks up the change on its next load, no redeploy.

Flagged attempts

Expired or forged codes and duplicate check-ins — seeded from local storage so it's here even offline, then merged with every device's flags from the flagged_scans table (updates live via Realtime, needs Replication enabled). Each row shows when this device saw it (Scanned) and when the cloud confirmed the write (Received) — a row still saying "Received —" hasn't synced yet.
